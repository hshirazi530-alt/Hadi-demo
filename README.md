# هژیر مارکت

فروشگاه فارسی و راست‌چین ابزارهای مراقبت شخصی مردانه، ساخته‌شده با Django. پروژه شامل کاتالوگ محصولات، سبد خرید، ثبت سفارش، پنل مدیریت، محتوای صفحهٔ اصلی، تأیید دیدگاه‌ها و اتصال آمادهٔ درگاه زرین‌پال است.

## نیازمندی‌ها

- Python 3.11 یا بالاتر
- PostgreSQL 14 یا بالاتر برای اجرای توسعه و انتشار
- شناسهٔ پذیرندهٔ زرین‌پال فقط برای دریافت وجه واقعی (در مخزن عمداً خالی است)

## راه‌اندازی در Windows

از پوشهٔ `Ecomprj` دستورات زیر را در PowerShell اجرا کنید:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

در فایل `.env` مقدار `DATABASE_URL` را با اطلاعات PostgreSQL محلی خود تنظیم کنید:

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@127.0.0.1:5432/hejrmarket
```

سپس پایگاه‌داده را آماده و محتوای نمایشی را بارگذاری کنید:

```powershell
python manage.py migrate
python manage.py load_demo_data
python manage.py createsuperuser
python manage.py runserver
```

سایت در `http://127.0.0.1:8000/` و پنل مدیریت در `http://127.0.0.1:8000/admin/` در دسترس خواهد بود. برای آزمون‌ها، پایگاه‌دادهٔ موقت SQLite در حافظه استفاده می‌شود و نیازی به تنظیم مجزای PostgreSQL نیست.

## تنظیمات محیطی

نمونهٔ متغیرها در `.env.example` قرار دارد. فایل `.env` را به مخزن اضافه نکنید.

| متغیر | کاربرد |
| --- | --- |
| `DJANGO_DEBUG` | حالت توسعه؛ در انتشار `false` باشد. |
| `DJANGO_SECRET_KEY` | کلید محرمانهٔ منحصربه‌فرد محیط؛ در انتشار الزامی است. |
| `DJANGO_ALLOWED_HOSTS` | نام میزبان‌ها، جداشده با کاما. |
| `DJANGO_PRODUCT_IMAGE_SOURCE_DIR` | اختیاری؛ مسیر پوشهٔ تصاویر که خود فرایند Django به آن دسترسی دارد. پیش‌فرض، پوشهٔ `img products` در کنار ریشهٔ پروژه است؛ در میزبان ابریِ فاقد آن پوشه از بارگذاری فایل استفاده کنید. |
| `DATABASE_URL` | نشانی اتصال PostgreSQL. اگر خالی باشد، تنظیمات به SQLite محلی برمی‌گردد. |
| `DJANGO_SITE_DOMAIN` | دامنهٔ بدون scheme، برای پیوندهای سایت‌مپ؛ پیش‌فرض `localhost:8000` است. |
| `ZARINPAL_MERCHANT_ID` | شناسهٔ پذیرنده؛ تا زمان دریافت شناسه خالی بماند. |
| `ZARINPAL_SANDBOX` | استفاده از محیط آزمایشی زرین‌پال؛ پیش‌فرض روشن است. |

پرداخت واقعی فقط برای سفارش‌های بدون کالای نمونه و با شناسهٔ پذیرندهٔ معتبر فعال می‌شود. مبلغ به ریال برای درگاه ارسال می‌شود و سفارش فقط پس از تأیید سمت سرور پرداخت‌شده ثبت خواهد شد. پرداخت آزمایشی فروشگاه هیچ مبلغی دریافت یا سفارش را پرداخت‌شده نمی‌کند.

## محصولات و محتوای نمایشی

فرمان زیر به‌صورت تکرارپذیر کالاهای نمونه، FAQ، مزیت‌های فروشگاه، بنر و پک پیشنهادی را آماده می‌کند:

```powershell
python manage.py load_demo_data
```

اطلاعات نمونه، قیمت‌ها و موجودی واقعی نیستند. کالاهای دارای برچسب «نمونه» برای نمایش روند فروشگاه‌اند و از درگاه واقعی قابل پرداخت نیستند.

## تعویض تصاویر از پنل مدیریت

1. از بخش **محصولات**، محصول را باز کنید و تصویر اصلی را با بارگذاری فایل جدید عوض کنید؛ تصاویر گالری همان‌جا در بخش تصاویر محصول مدیریت می‌شوند.
2. از بخش **بنرهای اصلی**، بنر فعال را باز کنید و تصویر و متن جایگزین آن را به‌روزرسانی کنید.
3. تصویر پک‌ها در بخش **پک‌های پیشنهادی** قابل ویرایش است.
4. تصاویر آپلودشده در `MEDIA_ROOT` ذخیره می‌شوند؛ در انتشار، مسیر رسانه باید روی ذخیره‌ساز پایدار و وب‌سرور پیکربندی شود.

فرمان `load_demo_data` فایل تصویر بنر نمونه را در `media/storefront/banners/barber-hero.jpg` قرار می‌دهد. تصویرهای محصولات نمونه در `media/store-samples/` کپی می‌شوند. اطلاعات منبع تصویر Unsplash و محدودهٔ استفاده در [IMAGE_CREDITS.md](./IMAGE_CREDITS.md) آمده است.

## افزودن محصول واقعی

در پنل سفارشی، به **افزودن محصول** بروید. تصاویر معتبر پوشهٔ منبع به‌صورت پیش‌نمایش نمایش داده می‌شوند؛ برای هر محصول، مدیر تصاویر را دستی انتخاب می‌کند و تصویر اصلی را جداگانه مشخص می‌کند. فایل‌های نامعتبر یا بزرگ‌تر از حد مجاز با خطا مشخص و غیرقابل انتخاب‌اند. نام فایل‌های تصویری این پوشه تطبیق خودکار مطمئنی با محصول ندارند. در صورت نبود دسترسی سرور به پوشه، از انتخاب پوشه/چند فایل در مرورگر استفاده کنید. مرورگر به‌تنهایی نمی‌تواند مسیر محلی Windows را بخواند.

عنوان، توضیحات فارسی مبتنی بر اطلاعات تأییدشده، قیمت واقعی مثبت، موجودی، دسته‌بندی و برچسب‌ها باید تکمیل شوند. عنوان تکراری رد می‌شود. تصاویر JPEG، PNG و WebP با حداکثر ۱۰ مگابایت برای هر فایل، مجموع ۶۰ مگابایت و حداکثر ۲۰ تصویر، در سمت سرور به WebP تبدیل می‌شوند و در `MEDIA_ROOT` ذخیره می‌شوند. پیش از ثبت، مدیر تصویر اصلی/گالری و جزئیات را بازبینی و تأیید می‌کند؛ وضعیت پیش‌فرض محصول «در حال بررسی» است. قیمت یا مشخصات نامعلوم را وارد نکنید و حدس نزنید.

مدل فعلی فیلد مستقلی برای توضیح کوتاه، عنوان/توضیح SEO یا slug محصول ندارد. عنوان و ابتدای توضیحات برای متادیتای موجود استفاده می‌شوند و نشانی محصول بر پایهٔ شناسهٔ موجود است. برای استفاده از منبع تصاویر در سرور دیگر، `DJANGO_PRODUCT_IMAGE_SOURCE_DIR` را به پوشه‌ای تغییر دهید که فرایند Django واقعاً به آن دسترسی دارد؛ مسیر رایانهٔ مدیر از مرورگر به سرور منتقل نمی‌شود.

## SEO و فایل‌های استاتیک

- متادیتای صفحه، Open Graph و نشانی canonical در قالب پایه تنظیم شده‌اند.
- نشانی‌های `/sitemap.xml` و `/robots.txt` در دسترس هستند.
- دادهٔ ساختاریافتهٔ محصولات در صفحهٔ جزئیات محصول خروجی داده می‌شود.
- برای آماده‌سازی فایل‌های استاتیک انتشار:

```powershell
python manage.py collectstatic --noinput
```

WhiteNoise برای ارائهٔ فایل‌های استاتیک پیکربندی شده است. بارگذاری رسانهٔ کاربران در انتشار نیازمند سرویس یا ذخیره‌ساز رسانهٔ پایدار است.
